# Contributing

Develop in a disposable WordPress installation using the developer guide. Use synthetic fixtures, never customer exports or production credentials. Include a regression test for each defect, recheck ZIP contents and test changes with the minimum relevant capability. Preserve existing tables and records when changing migrations. Document user-facing changes in the changelog. Run both WordPress Coding Standards and PHP compatibility scans; do not disable failing checks to approve a release.

For private disclosure, follow [SECURITY.md](SECURITY.md), not a public pull request.
